# Talaash Heritage: a heritage-learning platform, built and run end to end

**Live:** https://talaash-heritage.pages.dev · **Built and operated by** [Pryank Wadhera](https://www.linkedin.com/in/pryankwadhera) (product, design, engineering and content operations)

Talaash Heritage sells heritage walks, courses, lectures and counselling across archaeology, linguistics, anthropology, the arts, Sanskrit, history and heritage. This repository is the whole product: the website, the payments back end, the content pipeline and the automation that publishes to social media.

## What it does

- **Programme catalogue and finder.** 165 programmes, each with its own page, generated from one source file. A "Help me choose a programme" finder matches visitors to programmes by topic, place and length.
- **Learn hub.** 137 long-form guides, written to a house spec and checked by script (links, length, cross-sell fields) before they publish. Every guide links to the programmes it relates to, and every programme page links back to its guides.
- **Interactive 3D reconstructions.** Monuments rebuilt in three.js from published surveys, with every element tagged by evidence (Measured, Documented, Estimated and so on), so visitors can see what is known and what is inferred.
- **Heritage desk.** A daily news section (21 stories so far) built from JSON, with its own sitemap.
- **Payments.** Card, netbanking and UPI through Razorpay, with order creation, verification and webhooks on Supabase Edge Functions. Registration is taken at checkout only, so browsing never asks for details.
- **Bilingual.** A full Hindi interface, generated by a build step that refuses any translation that drops a link or tag.
- **On-site assistant.** A help assistant on Cloudflare Workers AI that answers only from the site's own guides and hands over to WhatsApp when unsure. It never quotes a price.

## How it is built

| Layer | Choice | Why |
|---|---|---|
| Hosting | Cloudflare Pages, deployed from `main` | Free, global, about a minute from push to live |
| Data and auth | Supabase (Postgres, Edge Functions) | Orders, bookings and products with row-level security |
| Payments | Razorpay | Indian cards, netbanking and UPI |
| Site generation | Python build scripts in `tools/` | One source of truth per content type, no framework lock-in |
| Automation | GitHub Actions | Social slides rendered in headless Chromium, clean URLs and IndexNow on every push, weekly release checks |
| Social publishing | Make scenarios reading a Google Sheet queue | Scheduled posting to Instagram and Facebook with a per-post compliance gate |

## Product decisions worth noting

- **No prices on public pages.** Every programme is quoted per group, so pages sell with language and a group-size picker that fills the enquiry; fees appear only where a buyer pays online.
- **Evidence over decoration.** Reconstructions show only what published surveys support, and every claim in public content passes three independent checks before it goes out.
- **Zero running cost.** Free tiers throughout; nothing depends on a laptop being switched on.
- **Search first.** Canonical clean URLs, separate sitemaps for guides, news and 3D pages, IndexNow pings on every change, and `llms.txt` for answer engines.

## Operating notes

The website lives in `site/`. Cloudflare Pages publishes that folder.

Configuration: `site/assets/js/config.js` (public values only, never the Supabase service_role key).

Live site: https://talaash-heritage.pages.dev (auto-deploys from main via Cloudflare Pages).

Every push to `main` goes live automatically.

Programmes run on request are listed in `site/data/catalogue.json`, which is generated by `python3 tools/build_catalogue.py site/data/catalogue.json`. Edit the programme text, the what-it-covers lines and the practical details in that script, then run it. The same run rewrites the programme cards inside `site/shop.html` (between the `catalogue:start` and `catalogue:end` markers, so search engines and visitors without JavaScript see every programme) and `site/sitemap.xml`. The programme finder (`finder.html`) reads each programme's `find` tags (topics, places, lengths), which are also set in that script. The same file hides or relabels database listings that are not on sale yet. Dated, paid events are added in the admin page.

## Hindi

The language switch (English | हिन्दी) sits above the header and on the registration form. The choice is kept in the browser; a visitor whose browser is set to Hindi starts in Hindi.
The Hindi lives in `tools/build_hindi.py`. Edit it there and run `python3 tools/build_hindi.py` to regenerate `site/assets/js/hi.js`; the build refuses translations that drop a link or tag.
Phase one covers the interface, home, catalogue, finder, contact, Journeys, Our work, registration and the WhatsApp/email messages. Programme descriptions, About, policies, cart and checkout are still English, with a Hindi notice on those pages.

## Payments

UPI and WhatsApp orders need no server. Card, netbanking and UPI through Razorpay use three Supabase functions in `supabase/functions`; setup is in `docs/RAZORPAY.md`.

## Learn section, SEO and marketing files

The guides (Learn menu) are JSON files in `content/guides/`, written to `content/SPEC.md`. Each guide also holds its Google Ads ad group, social posts and share text.

- `python3 tools/check_guides.py`: checks every guide (links, length, banned words, cross-sell and marketing fields).
- `content/extra_programmes.json`: programmes written by hand outside the programme bank (the National Museum, Old Delhi's Chandni Chowk, the Agra day trip). Same fields as `tools/bank.json`, plus `when` and `practical`; `build_catalogue.py` adds them. Weekly closing days that the general wording would get wrong are in `WHEN` in `build_catalogue.py`.
- `python3 tools/build_learn.py`: writes the guide pages, `site/learn.html`, `site/sitemap-guides.xml`, `site/llms.txt`, the header search index `site/data/search.json` and `site/data/programmes.json`. Run it after `build_catalogue.py`.
- `python3 tools/export_marketing.py [start date]`: writes `docs/marketing/` (keyword map, Google Ads Editor import, 90-day social calendar, page register).

`build_catalogue.py` reads the guides too: programme pages show "Pairs well with" (from the guides' bundles) and "Read before you go" (guides that recommend the programme).

## Heritage desk (news)

Stories are JSON files in `content/news/` (rules in `content/news/README.md`). `python3 tools/build_news.py` writes `site/news.html`, one `site/news-<slug>.html` per story and `site/sitemap-news.xml`; `--check` validates only. "News" is in the header, the footer and the mobile menu.

## Site assistant

The help panel ("Ask Khoji") holds Khoji, an AI assistant on Cloudflare Workers AI (free allowance): `site/assets/js/assistant.js` calls `functions/api/assist.ts`. Rules and general facts are in `functions/_lib/assist-rules.ts`; programme and guide facts in `functions/_lib/assist-data.json`, written by `tools/build_assist.py` (`build_learn.py` runs it). Payment and refund answers come word for word from `site/assets/js/help-answers.js`. It never quotes a price: price questions go to the programme page. The AI binding is in `wrangler.toml`. Daily limits: `public.assist_take`, 100 replies for the site and 20 per visitor. `node tools/assist-check.mjs <address>` asks it a fixed set of questions.

## Social media images

Instagram and Facebook slides are rendered by the GitHub Action in `.github/workflows/render-slides.yml` from `render/queue/<post>/<n>.html` to `site/media/ig/<post>-<n>.jpg` (see `render/README.md`), and served from `https://talaash-heritage.pages.dev/media/ig/`.
