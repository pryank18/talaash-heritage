# Talaash Heritage store

The website lives in `site/`. Cloudflare Pages publishes that folder.

Configuration: `site/assets/js/config.js` (public values only, never the Supabase service_role key).

Live site: https://talaash-heritage.pages.dev (auto-deploys from main via Cloudflare Pages).

Every push to `main` goes live automatically.

Programmes run on request are listed in `site/data/catalogue.json`, which is generated by `python3 tools/build_catalogue.py site/data/catalogue.json`. Edit the programme text, the what-it-covers lines and the practical details in that script, then run it. The same run rewrites the programme cards inside `site/shop.html` (between the `catalogue:start` and `catalogue:end` markers, so search engines and visitors without JavaScript see every programme) and `site/sitemap.xml`. The programme finder (`finder.html`) reads each programme's `find` tags (topics, places, lengths), which are also set in that script. The same file hides or relabels database listings that are not on sale yet. Dated, paid events are added in the admin page.

## Hindi

The language switch (English | हिन्दी) sits above the header and on the registration form. The choice is kept in the browser; a visitor whose browser is set to Hindi starts in Hindi.
The Hindi lives in `tools/build_hindi.py`. Edit it there and run `python3 tools/build_hindi.py` to regenerate `site/assets/js/hi.js`; the build refuses translations that drop a link or tag.
Phase one covers the interface, home, catalogue, finder, contact, Journeys, Our work, registration and the WhatsApp/email messages. Programme descriptions, About, policies, cart and checkout are still English, with a Hindi notice on those pages.

## Payments

UPI and WhatsApp orders need no server. Card, netbanking and UPI through Razorpay use three Supabase functions in `supabase/functions`; setup is in `docs/RAZORPAY.md`.

## Learn section, SEO and marketing files

The guides (Learn menu) are JSON files in `content/guides/`, written to `content/SPEC.md`. Each guide also holds its Google Ads ad group, social posts and share text.

- `python3 tools/check_guides.py`: checks every guide (links, length, banned words, cross-sell and marketing fields).
- `content/extra_programmes.json`: programmes written by hand outside the programme bank (the National Museum, Old Delhi's Chandni Chowk, the Agra day trip). Same fields as `tools/bank.json`, plus `when` and `practical`; `build_catalogue.py` adds them. Weekly closing days that the general wording would get wrong are in `WHEN` in `build_catalogue.py`.
- `python3 tools/build_learn.py`: writes the guide pages, `site/learn.html`, `site/sitemap-guides.xml`, `site/llms.txt`, the header search index `site/data/search.json` and `site/data/programmes.json`. Run it after `build_catalogue.py`.
- `python3 tools/export_marketing.py [start date]`: writes `docs/marketing/` (keyword map, Google Ads Editor import, 90-day social calendar, page register).

`build_catalogue.py` reads the guides too: programme pages show "Pairs well with" (from the guides' bundles) and "Read before you go" (guides that recommend the programme).

## Heritage desk (news)

Stories are JSON files in `content/news/` (rules in `content/news/README.md`). `python3 tools/build_news.py` writes `site/news.html`, one `site/news-<slug>.html` per story and `site/sitemap-news.xml`; `--check` validates only. "News" is in the header, the footer and the mobile menu.

## Social media images

Instagram and Facebook slides are rendered by the GitHub Action in `.github/workflows/render-slides.yml` from `render/queue/<post>/<n>.html` to `site/media/ig/<post>-<n>.jpg` (see `render/README.md`), and served from `https://talaash-heritage.pages.dev/media/ig/`.
